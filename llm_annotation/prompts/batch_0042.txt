# DÉFINITIONS DES 9 LABELS

**VERROU_TECH**
- Définition : Obstacle, difficulté, problème technique/scientifique CONCRET à résoudre
- ✅ Exemples valides :
     - "manque de précision des capteurs actuels"
     - "absence de modèle prédictif fiable pour la respiration cellulaire"
     - "instabilité de la nano-émulsion à température ambiante"
     - "difficulté de vectorisation de la perfluorodécaline"
- ❌ NE PAS annoter :
     - "le projet (trop générique)"
     - "problème (vague sans précision)"
     - "défi (sans contexte)"

**METHODE_RD**
- Définition : Approche, méthodologie, démarche scientifique précise
- ✅ Exemples valides :
     - "évaluation ex vivo sur explants de peau humaine"
     - "analyse par cytométrie en flux"
     - "méthode Monte Carlo"
     - "test in vitro sur kératinocytes"
- ❌ NE PAS annoter :
     - "méthode (sans précision)"
     - "étude (vague)"

**TECHNOLOGIE_RD**
- Définition : Technologie, framework, plateforme ou paradigme technique
- ✅ Exemples valides :
     - "nano-émulsion"
     - "deep learning"
     - "spectroscopie Raman"
     - "encapsulation liposomale"
- ❌ NE PAS annoter :
     - "technologie (générique)"
     - "informatique (trop large)"

**EQUIPEMENT_RD**
- Définition : Équipement physique, machine, instrument utilisé
- ✅ Exemples valides :
     - "microscope à fluorescence"
     - "cytomètre en flux"
     - "spectromètre de masse"
     - "banc d'essai thermique"
- ❌ NE PAS annoter :
     - "machine (générique)"
     - "ordinateur (sans spec)"

**COMPOSANT_TECHNIQUE**
- Définition : Composant, élément technique d'un système ou produit
- ✅ Exemples valides :
     - "vectorisateur lipidique"
     - "capteur infrarouge"
     - "algorithme de tri"
     - "complexe oxygénant"
- ❌ NE PAS annoter :
     - "composant (générique)"
     - "système (trop vague)"

**MATERIAU_SPECIFIQUE**
- Définition : Matériau, substance ou molécule spécifique nommée
- ✅ Exemples valides :
     - "perfluorodécaline"
     - "mélatonine"
     - "acide hyaluronique"
     - "polymère biosourcé PLA"
- ❌ NE PAS annoter :
     - "matériau (générique)"
     - "produit (vague)"

**DOMAINE_RD**
- Définition : Domaine scientifique, secteur d'application, champ disciplinaire
- ✅ Exemples valides :
     - "cosmétique"
     - "respiration cellulaire"
     - "intelligence artificielle"
     - "dermatologie"
- ❌ NE PAS annoter :
     - "recherche (trop générique)"
     - "science (trop large)"

**RESULTAT_RD**
- Définition : Résultat concret obtenu, performance mesurée, livrable
- ✅ Exemples valides :
     - "augmentation de 30% de l'oxygénation cellulaire"
     - "prototype fonctionnel validé"
     - "brevet déposé EP123456"
- ❌ NE PAS annoter :
     - "résultat (générique)"
     - "succès (vague)"

**OBJECTIF_RD**
- Définition : Objectif, but ou cible visée par le projet
- ✅ Exemples valides :
     - "stimuler la respiration cellulaire"
     - "développer un système autonome"
     - "identifier de nouveaux actifs"
- ❌ NE PAS annoter :
     - "but (générique)"
     - "amélioration (sans précision)"

# RÈGLES STRICTES

1. **N'annote QUE ce qui correspond CLAIREMENT à une catégorie**
2. **NE JAMAIS inventer** d'entités absentes du texte
3. Les positions `start` et `end` doivent être **EXACTES** (positions de caractère dans le chunk)
4. **Préfère ne pas annoter** plutôt que d'annoter incorrectement
5. Les entités doivent être **SPÉCIFIQUES** (pas trop génériques)
6. **Évite les chevauchements** entre entités
7. Vérification : `chunk_text[start:end] == entity_text` doit être VRAI

[SECTION : Première itération : évaluation des modèles de traitement de langage existants]
Dans cette première partie de nos travaux, nous avons évalué les performances des modèles Transformers déjà existants en vue de résoudre notre problématique. Pour cela, nous avons décidé d’entrainer les trois modèles suivants :

Modèle n°1 : Le modèle DistilCamemBERT affiné pour la tâche d’inférence du langage naturel (NLI) pour la langue française ;

Pour ce faire nous avons effectué un réglage (Fine Tuning) sur les trois modèles en s’appuyant sur des données personnalisées. Cependant, nous avons obtenu des performances non satisfaisantes.

Figure 1 : Performances des modèles DistilCamemBERT, mDeBERTa et bart-large pour la tâche de classification automatique.

Le tableau ci-dessus présente les résultats obtenus pour les trois modèles mis en œuvre en termes d'exactitude (accuracy) et de score F1. Ces métriques sont employées pour évaluer les performances des modèles dans la classification des thèmes définis.

Le modèle DistilCamemBERT affiche une exactitude de 61 % et un score F1 de 60 %. Ces résultats montrent que ce modèle a des performances non satisfaisantes dans la classification des textes. L'exactitude indique qu'environ 61 % des prédictions du modèle sont correctes, tandis que le score F1, légèrement inférieur, indique un équilibre entre la précision (proportion de vraies prédictions parmi les prédictions positives) et le rappel (proportion de vraies prédictions positives parmi les cas positifs réels), ce qui signifie que le modèle a une performance équilibrée mais pas optimale.
