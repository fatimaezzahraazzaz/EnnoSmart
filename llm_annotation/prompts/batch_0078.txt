[SECTION : État de l’art]
La validation des algorithmes dans le développement des systèmes ADAS/AD (Advanced Driver Assistance Systems / Autonomous Driving) présente des défis majeurs. En effet, elle repose sur l’intégration de plusieurs domaines scientifiques, incluant la mécanique, l’électricité, le contrôle, la communication et l’informatique. La diversité des disciplines implique une approche modulaire où chaque domaine peut être simulé par un outil dédié. Toutefois, l’absence de solutions génériques pour assurer une co-simulation fluide entre ces outils constitue une problématique centrale.

Pour répondre à cette exigence, plusieurs standards ont été introduits :

Le standard DCP (Distributed Co-Simulation Protocol) :

Proposé par l’association Modelica, le DCP [1] [2] a été conçu pour standardiser la co-simulation distribuée entre des outils hétérogènes. Contrairement à d’autres approches comme le FMI (Functional Mock-up Interface), le DCP vise à assurer une communication temps réel entre plusieurs simulateurs connectés via un réseau. Il permet ainsi de synchroniser les échanges de données tout en garantissant des performances optimales pour des environnements complexes, comme les simulations ADAS/AD.

L’utilisation du DCP dans des environnements de simulation 3D, tels que CARLA, est essentielle pour tester les algorithmes dans des scénarios réalistes où les capteurs, les conditions de l’environnement et les interactions avec le trafic sont pris en compte. Néanmoins, à l’époque de nos travaux, le DCP était encore immature et nécessitait une étude approfondie pour son implémentation dans une plateforme temps réel comme xMOD.

Le standard ASAM XIL API :

La XIL API [3], développée par l’organisation ASAM, est une norme permettant la communication entre les outils d’automatisation et les bancs d’essais. Elle dissocie les logiciels de test des systèmes sous test (réels ou virtuels), facilitant ainsi la réutilisation des cas de test et l’intégration dans des chaînes d’outils existantes. La XIL API supporte plusieurs niveaux de test dans le processus de développement :

Model-In-the-Loop (MIL)

Software-In-the-Loop (SIL)

Processor-In-the-Loop (PIL)

Hardware-In-the-Loop (HIL)
